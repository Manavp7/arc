# Source-derived zone access

Access is derived from the authenticated principal and stored source metadata. Passing `zone_id` in a URL never grants access. An empty zone claim means unrestricted access, as before; administrators retain their policy bypass. For an explicitly restricted token, missing/unknown source membership is denied rather than treated as public.

The live REST read model applies zone predicates before pagination and aggregation. Entity history and reconstructed worlds use membership at the historical timestamp. GraphQL, including nested fields and subscriptions, uses the same scope; SSE and WebSocket fan-out filters source-identified entities, events and alerts before enqueueing; tracks, decisions and aggregate forecasts are withheld from restricted streams until they carry an authoritative source projection. Replays belong to the creating account, and streaming intersects the original scope with the account's current scope.

Each stored recording, retained version and saved source snapshot must independently establish its own known scope; another record or a proposed edit cannot grant access to an unknown source. Legacy snapshots without any known zone remain unavailable to restricted accounts until an authorized repair or fresh analysis. Recorded lists, exact retained analyses, playback, posters, evidence frames, configuration, analysis and job operations enforce current recording and retained-version scopes. Archived media cannot be fetched through an old direct link. Restricted accounts must select `access_zone_id` when uploading MP4 bytes; this is stored access-control metadata, independent of drawn image zones. Recorded search, bookmarks and capture clocks use the same source checks.

The media gateway resolves a stored frame's registered source before serving it to a restricted account. Unindexed media cannot establish a source scope. Camera geometry responses do not return connector configuration or credentials.

Whole-site forecasts, missions, analytics, live semantic frame search, copilot, agent activity, simulation, source and authored-workflow configuration, site/camera commissioning, system operations and governance audit currently lack a complete zone-filtered projection. Explicitly zone-restricted accounts receive an actionable 403 at the API and supported direct-service entry points for these surfaces. Unrestricted accounts continue to use them. Filtering an already aggregated or AI-generated answer is not considered a safe substitute. This limitation is enforced and must be removed only when the underlying service can apply scope before reading or computing.

`GET /api/audit` forwards to the governance audit trail and supports `actor`, `action`, `allowed`, `since_minutes`, and `limit`. `GET /api/agents/audit` remains a distinct agent-activity view.

HTTP MCP is a deployment-administrator interface because its configured tool belt delegates to a service identity. It always requires a bearer token, even when other development HTTP authentication is disabled, rejects other deployment tenants, and audits authenticated permission decisions. Local stdio remains a trusted subprocess interface. MCP clients must supply an administrator token for the configured tenant; restricted end-user MCP delegation is not implemented.
